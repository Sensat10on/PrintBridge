# Known Limitations

This file lists what PrintBridge deliberately does **not** verify. Everything not listed here is
covered by automated tests in the corresponding module.

## Not verified against hardware

Physical print quality, paper feeding, gap/black-mark detection, cutter behaviour, print-head
behaviour, real status responses (`PaperOut`, `CoverOpen`, `PrinterBusy` are modelled but never
observed from a device), real buffer limits, vendor firmware quirks, label calibration, and
printing over USB, Bluetooth SPP and raw TCP.

App installation *is* verified: the debug APK was installed and launched on a Galaxy S25
(SM-S931W, Android 16) with no `FATAL EXCEPTION`. Layout was checked on that device only — a
small phone and a large tablet remain unverified.

No transport failure mode should be treated as "supported" until it has been reproduced on a real
printer; `docs/TESTING_WITHOUT_PRINTER.md` describes the levels that *are* covered.

## Protocol coverage

- ESC/POS: the receipt subset generated by `EscPosDriver` (initialize, align, bold, scale, feed,
  cut, QR, raster). Not implemented: code pages, status queries, cash drawer, barcode symbologies.
- TSPL: the subset generated by `TsplDriver`. Not implemented: RFID, cutter configuration,
  counters, font download.
- GOOJPRT/MTP: label command families ported from the vendor SDK, marked `verified = false` until
  confirmed on a physical GOOJPRT/MTP printer.
- ZPL, CPCL, EPL: declared in the protocol enum but have no driver; `buildReadyJob` returns an
  empty payload for them.
- BLE: declared as a transport type but not implemented.

## File printing

`ПЕЧАТЬ ФАЙЛА` prints a user-selected image, PDF or text file.

- Images are decoded with `BitmapFactory` using `inSampleSize`, scaled to the printer width and
  thresholded to 1 bit. Transparency is treated as white paper, not black ink.
- PDF rendering uses the platform `PdfRenderer`, which needs API 21+ and cannot be exercised in
  unit tests; only the rasterisation of a rendered page is covered. Pages are capped at
  `FilePrintPipeline.MAX_OUTPUT_DOTS_HEIGHT` (8 000 dots) to bound memory — a very tall page is
  cut off rather than failing the job.
- A PDF with more pages than the 50-page cap prints only the first 50.
- Plain text and CSV are wrapped to the printer column count and are limited to 512 KB. Detection
  is BOM, then strict UTF-8, then Windows-1251; other legacy code pages are not detected.
- Rendering quality on thermal paper (density, gamma, dithering) is not verified. Only a fixed
  luminance threshold is applied; there is no dithering option in the UI.
- Nothing here has been printed on a physical printer.

## Launcher icons

Each flavour ships its own artwork, declared in its manifest (`app/src/<flavour>/AndroidManifest.xml`)
because the icon differs per build:

| Flavour | Icon | Resource |
|---|---|---|
| `paid` | FREE badge | `app/src/paid/res/mipmap-xxhdpi/ic_launcher_free.png` |
| `full` | TEST badge | `app/src/full/res/mipmap-xxhdpi/ic_launcher_test.png` |

- The **PRO artwork is staged but not active**: `ic_launcher_pro_option.png` ships inside the `paid`
  APK next to the FREE one, ready for the purchase flow. Android cannot repaint a launcher icon on
  a purchase silently — the app has to enable a differently-named `activity-alias` carrying the PRO
  icon and then ask the launcher to refresh, which is a follow-up to the Billing work rather than
  something faked here.
- The artwork is a finished rounded square, so it is shipped as a legacy (non-adaptive) icon at
  1254x1254 in `mipmap-xxhdpi`. Letting Android scale it from one density keeps the file intact
  instead of resampling and re-encoding it per density.
- Themed icons (Android 13+) are not provided; a 3D render does not reduce to a usable monochrome
  silhouette.

## Free and paid versions

Two product flavours are built from the same sources, and the difference is a **compile-time**
flag (`BuildConfig.FREE_TIER_ENFORCED`) rather than a runtime switch, so a shipped APK cannot turn
the limits off:

| Flavour | Package | Behaviour |
|---|---|---|
| `paid` | `com.printbridge.app` | Enforces the free tier; this is the build that ships |
| `full` | `com.printbridge.app.full`, version `…-full` | Internal test build: everything unlocked, no watermark |

In the `paid` build two rules describe the entitlement:

1. **One sheet per print command.** The free version prints a single sheet — the first page of a
   multi-page PDF, one copy of an image, one copy of a template. A page selector shows the other
   pages as "только в платной версии", and the copies selector stops at one, so the UI never
   offers something the print path would refuse.
2. **Every unlicensed print carries a watermark**, applied by `WatermarkComposer` to the ESC/POS,
   TSPL and GOOJPRT byte streams just before the transport. The text is editable per profile.

Each sheet is sent as its own queue job, so a thermal printer cuts between copies and every sheet
gets its own connection and completion state. A failure stops the batch instead of queueing the
rest into a printer that is already gone.

- Google Play Billing is **not** integrated. `LicenseStore` keeps a local boolean and the
  diagnostics screen has development buttons to grant and revoke it; a real purchase flow, receipt
  validation and restore-on-reinstall are not implemented.
- Because the entitlement is a local flag, it is trivially bypassable. It exists to wire the free
  and paid paths, not to enforce them.
- Backup is disabled (`allowBackup="false"`), so the entitlement does not survive reinstall.
- The copies selector is capped at `LicenseStore.MAX_SELECTABLE_COPIES` (20) regardless of the
  entitlement.
- The screen picker, the file section layout, the transport labels and the diagnostics text of both
  flavours were checked by hand on a Galaxy S25. The page selector and the copies stepper have
  **not** been exercised by hand on a device yet: open `ПЕЧАТЬ ФАЙЛА` with a multi-page PDF in the
  `paid` build and confirm that only the first page is selectable, then grant the licence in
  `ДИАГНОСТИКА` and confirm the rest become selectable.

## TSPL character encoding

Consumer TSPL firmware is single-code-page: one byte is one glyph. `TsplDriver` therefore writes
label text in a configurable `Charset` (`TsplText.DEFAULT_CHARSET`, ISO-8859-1 by default) instead
of silently replacing every non-ASCII character with `?` as it used to.

Consequences:

- Latin-1 text round-trips; ASCII command keywords are unaffected.
- Cyrillic and other scripts need a matching code page. Pass it explicitly, e.g.
  `TsplDriver().build(profile, charset = Charset.forName("windows-1251")) { ... }`, and make sure
  the printer is configured for the same page. There is no profile field for this yet.
- Characters the code page cannot represent become `?`; the job still prints.
- Label values are escaped for a TSPL `"..."` literal: control characters (including newline)
  become spaces and `"` becomes `\"`, so a label value can never inject an extra TSPL command.
  A literal backslash inside a value is written as-is and is not escaped, because the escape
  syntax of third-party firmware is not known yet; no UI field currently accepts one.

## Timeouts

`TcpPrinterTransport` bounds connect and every write. `BluetoothSppPrinterTransport` and
`UsbPrinterTransport` bound blocking IO with `withIoDeadline` (default 10 s / 5 s, configurable per
profile). A stalled Bluetooth write closes the socket to release the worker thread; the actual
recovery time on a given device is not verified.

## Network discovery

`NetworkPrinterDiscovery` probes common raw-print ports on the local /24 and is limited to
`DEFAULT_MAX_CONCURRENT_PROBES` open sockets. It finds listening ports, not printers: any open
service on those ports is reported. It is not an mDNS/SNMP discovery implementation.

## Windows print bridge

The bridge listens on a raw TCP port with no authentication and forwards whatever it receives into
a Windows print queue. Bind it to `127.0.0.1` unless LAN clients must reach it, and treat the port
as trusted-network only. Jobs larger than `--max-job-bytes` (default 8 MiB) are rejected, and each
client connection has a read timeout.
